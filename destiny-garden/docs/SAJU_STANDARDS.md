# 사주 계산 기준 (SAJU_STANDARDS)

사주 계산은 **LLM이 아니라 결정론적 엔진**(`src/lib/saju/engine.ts`)이 수행합니다. 같은 입력은 항상 같은 결과를 냅니다.
천문 계산(절기 시각, 음양력 변환)은 `lunar-javascript`, 그 위의 명리 규칙(십성·지장간·합충형파해·신강신약·대운·세운·월운)은 자체 구현입니다.

## 1. 입력과 시각 처리
| 항목 | 기준 |
|---|---|
| 시각 | 입력한 한국 표준시(KST)를 그대로 사용 (기본) |
| 진태양시 보정 | 선택 옵션. 출생지 경도 − 동경 135° 를 4분/도로 환산 (서울 약 −32분). 기본 OFF, 켜면 시주/일주가 일반 만세력과 달라질 수 있음을 UI에 고지 |
| 음력 입력 | 음력 → 양력 변환 후 계산. 윤달은 별도 체크. 존재하지 않는 음력(윤달 없는 해의 윤달 등)은 거부 |
| 생시 미상 | **시주를 임의로 만들지 않음.** 시주 `null`, 십성·오행·신강신약은 연·월·일주만 사용, 안내 문구 표시 |
| 지원 범위 | 1900 ~ 2100 |

## 2. 기둥(柱)
- **연주**: 입춘(立春) 절입 시각 기준으로 교체 (양력 1월 1일·음력 설 아님).
- **월주**: 12절(입춘·경칩·청명·입하·망종·소서·입추·백로·한로·입동·대설·소한) **절입 시각(분 단위)** 기준. 월간은 오호둔(연상기월법).
- **일주**: 자정(00:00) 교체. 검증용 독립 계산(1900-01-01 = 갑술일 기준 일수 카운트)과 2,000개 표본이 일치함을 테스트로 확인.
- **시주**: 12지시(자시 23:00~01:00 등). 시간(時干)은 오서둔(일상기시법).
- **자시(야자시) 처리**: 기본 `same_day` — 23:00~23:59 출생은 일주는 당일, 시주는 子時(시간은 익일 일간 기준). 옵션 `next_day` — 23:00 부터 익일 일주. 한국 만세력 앱마다 기준이 달라 옵션으로 제공.

## 3. 파생 항목
- **오행**: 천간·지지 8자 기준 개수(`visible`) 및 지장간 가중 포함(`withHidden`: 정기 1, 중기 0.5, 여기 0.3).
- **지장간**: 표준 표 (예: 인 = 무·병·갑, 사 = 무·경·병, 해 = 무·갑·임). 정기가 십성 판단의 본기.
- **십성**: 일간 기준 오행 생극 + 음양 동이. 지지의 십성은 지장간 정기로 판단.
- **합충형파해**: 천간합·천간충, 지지 육합·삼합(왕지 포함 반합)·방합·충·형(삼형·무례지형·자형)·파·해. 원국 기둥 간 쌍을 전수 검사.
- **신강신약**: *자체 가중 기준*. 비겁·인성을 "아군"으로, 위치 가중치(월지 30, 일지 15, 월간·시간·시지 12, 연간·연지 8)의 합 비율로 극신약/신약/중화/신강/극신강 5단계 판정. 득령(월지)·득지(일지)·득세(연·월·시간 2개 이상) 별도 표시. **학파별로 다를 수 있는 항목**이며 전문가 검수 전 상태.
- **대운**: 양남음녀 순행/음남양녀 역행, 절입까지의 일수/3 = 대운 시작 나이(lunar-javascript 구현). 10개 기둥.
- **세운**: 해당 연도 간지(입춘 기준). **월운**: 해당 연도 12개월 간지 + 절입 시각.

## 4. 경계 경고
- 직전·다음 절기 시각을 결과에 포함. 절기 ±24시간 이내 출생이거나 자시 출생이면 사용자에게 경고.

## 5. 검증 (`tests/saju.test.ts`)
1995-04-17 14:30(여) = 乙亥·庚辰·戊寅·己未, 입춘 전후 연·월주 교체, 청명 절입 분 단위 경계, 윤달 변환(2020 윤4월 10일 = 2020-06-01), 자시 옵션, 생시 미상, 대운 순역행, 세운·월운, 진태양시 보정, 일주 독립 계산 2,000표본.
**남은 검증**: 한국천문연구원 API 교차 검증(`scripts/verify-kasi.ts`, `KASI_SERVICE_KEY` 필요)과 시중 한국 만세력 서비스와의 대조는 키·외부 접근이 필요해 이 환경에서 수행하지 못했습니다. 출시 전 필수.

## 6. 해석 데이터의 신뢰 수준
`data/*.json` 의 모든 해석 문장은 `source: "자체 작성 초안"`, `review_status: "pending"`(검토 대기)입니다. 명리 전문가 검수 후 `approved` 로 바꾸고, 운영에서는 `approved` 만 노출하도록 필터를 추가하세요.
